\section{Problem Formulation}

MUSCAT \cite{muscat2023} formulates sensor placement as a binary allocation of sensor types \(t\in T\) to candidate locations \(l\in L\), maximizing coverage minus a weighted cost under a budget. We keep the sets \(T\) and \(L\) but do not scalarize: cooperative (RID/RF-capable) and non-cooperative (dark-target) surveillance are not interchangeable \cite{besada2022cuas,blasch2021information,dulia2024sand}, so each layer is a separate objective.

\subsection{Encoding and Objectives}

A deployment is a list of genes
\begin{equation}
\textbf{X} = [(l_1, t_1, o_1, a_1), \ldots, (l_{n}, t_{n}, o_{n}, a_{n})],
\label{eq:chromosome}
\end{equation}
where \(l_i\in L\) is a candidate site (several genes may share a site), \(t_i\in T\) the sensor type, \(o_i\) an azimuth index in \(\{0^{\circ},120^{\circ},240^{\circ}\}\), and \(a_i\in\{0,1\}\) an activation bit. The length \(n\) is the maximum sensor count; at least the minimum count of genes stays active. Each deployment is scored by
\begin{equation}
F(\textbf{X}) = \bigl(M_{wp,\mathrm{coop}}(\textbf{X}),\; M_{wp,\mathrm{noncoop}}(\textbf{X}),\; C(\textbf{X})\bigr)
\label{eq:fitness}
\end{equation}
(maximize, maximize, minimize), with the coverage terms defined in Section~\ref{sec:dual_metrics}. CapEx counts hardware plus a site-activation fee for every distinct occupied site:
\begin{equation}
C(\textbf{X}) = \sum_{i:\,a_i=1} C_{t_i} + C_{\mathrm{site}}\,\bigl|\{l_i : a_i = 1\}\bigr|,
\label{eq:capex}
\end{equation}
with \(C_{\mathrm{site}}=\$15\mathrm{k}\) unless stated otherwise.

\subsection{Classic Coverage and Planning Floors}

Controls~A--B use MUSCAT's coverage index \cite{muscat2023},
\begin{equation}
\mc = n/N,
\label{eq:coverage_index}
\end{equation}
where \(n\) is the number of grid cells with network detection probability at least a threshold (0.8 here) and \(N\) the number of cells. All dual-layer fronts use \(M_{wp}\) instead. Rather than a single fused coverage threshold, we filter front members with joint planning floors on \(M_{wp,\mathrm{coop}}\) and \(M_{wp,\mathrm{noncoop}}\) (e.g., \(0.90/0.35\)), reflecting non-collaborative UTM surveillance needs \cite{besada2022cuas}.
