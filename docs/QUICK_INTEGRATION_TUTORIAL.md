# SCOPAS Quick Integration Tutorial

This is a fast path to integrate SCOPAS into your workflow in about 10 minutes.

## 1) Install and validate

```bash
pip install -r requirements.txt
python run_framework.py --config configs/quick_test.json --mode nsga2
```

If this runs, your environment is ready. The smoke test includes **Radar, RF, EO, and Acoustic**.

## 2) Choose an integration style

- **CLI-first (recommended for most users):** use configs and command line runs.
- **Python API integration:** call `evaluate_solution()` from your own optimizer loop.

## 3) CLI-first integration

### 3.1 Copy a template

```bash
cp configs/templates/dual_layer_template.json configs/my_scenario.json
```

Edit these keys in `configs/my_scenario.json`:
- `experiment_name`
- `environment.buildings_file`
- `environment.sensor_locations_file`
- `critical_assets`
- `output.run_id`

Templates already include Acoustic (non-cooperative, ~USD 8k / ~300 m urban). Details: `docs/SENSORS.md`.

### 3.2 Run optimization

```bash
python run_framework.py --config configs/my_scenario.json --mode nsga2
```

### 3.3 Run full analysis pipeline

```bash
python run_experiment.py --config configs/my_scenario.json --skip-3d
```

### 3.4 Optional split planning (practical operations)

```bash
python run_experiment.py --config configs/my_scenario.json --split-objectives
```

This gives two separate result sets:
- cooperative objective (`_coop`)
- non-cooperative objective (`_noncoop`) — Radar / EO / Acoustic (RF dropped)

### 3.5 Ready-made Acoustic demos

```bash
python run_experiment.py --config configs/demo_acoustic_dual_layer.json --skip-3d
python run_experiment.py --config configs/demo_acoustic_noncoop.json --skip-3d
python run_experiment.py --config configs/demo_acoustic_split.json --split-objectives --skip-3d
```

### 3.6 Target floors (coop / noncoop requirements)

Aim for explicit dual-layer floors, then filter the Pareto:

```bash
python run_experiment.py --config configs/demo_targets_coop90_noncoop35.json --skip-3d
python run_experiment.py --config configs/demo_targets_coop90_noncoop50.json --skip-3d

python tools/select_requirement_solutions.py \
  --results results/demo_targets_coop90_noncoop50/run_targets/ \
  --min-coop 0.90 --min-noncoop 0.35
```

Practical joint floor in short demos: **90% coop / 35% noncoop**. **50% noncoop** with ≥90% coop is a stretch. Details: `docs/DEMO_RUNS.md`.

## 4) Python API integration

Use this when you already have your own optimization algorithm.

```python
from src.scopas_core import load_config, load_environment_from_config, evaluate_solution

config = load_config("configs/my_scenario.json")
env = load_environment_from_config(config)
sensor_types = config["sensors"]["types"]

candidate = [
    {"type": "Radar", "x": 500, "y": 500, "z": 30},
    {"type": "RF", "x": 200, "y": 700, "z": 25},
    {"type": "Acoustic", "x": 350, "y": 450, "z": 20},
]

result = evaluate_solution(env, candidate, sensor_types, config=config)
print(result)
```

## 5) Where outputs are saved

Standard output folder:

```text
results/<experiment_name>/<run_id>/
```

Key files:
- `config.json`
- `evaluation_results.json`
- `pareto_front.json`
- `pareto_dual_layer_targets.png` (dual-layer runs)
- `requirement_solutions.json` (after `select_requirement_solutions.py`)
- plots and maps generated by tools

## 6) Common mistakes

- Wrong relative paths in config files.
- Running outside the project root.
- Using non-cooperative objective with RF-only sensor sets (RF is ignored for dark-target coverage).
- Comparing runs with different `resolution` or `pareto_search` settings.
- Expecting Acoustic to match Radar long-range performance — urban Acoustic default is ~300 m for quiet multi-rotors.
